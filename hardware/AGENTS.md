# Hardware guide

Guidance for the schematic, PCB and KiCad tooling under `hardware/`. The
repo-wide overview is in [`AGENTS.md`](../AGENTS.md); firmware and dashboard
work has its own guide in
[`docs/agents/firmware.md`](../docs/agents/firmware.md).

## Where things are

| Path | Contents |
|------|----------|
| `hardware/kicad/` | KiCad project. The schematic is generated by `tools/gen_schematic.py`; see [`kicad/README.md`](kicad/README.md). |
| `hardware/kicad/tools/` | Python generators and checks for the schematic, PCB, 3D models and fab export (run with KiCad's Python). |
| `hardware/kicad/lib/` | Project symbols, footprints and `cryocooler.3dshapes/` 3D models. |
| `hardware/kicad/fabrication/` | Gerbers, JLCPCB zip and board renders, written by `tools/export_fab.py`. |
| `hardware/HANDOFF_ucs125_rev3.md` | Current board (branch `ucs-125-87-rev3`): rev 3 on the 100 x 62 mm UCS 125-87 outline. |
| `hardware/HANDOFF_rev3.md` | Rev 3 on the UCS 145-125 board: status, PCB notes, bench list, open items. |
| `hardware/TODO.md` | Bench findings and open hardware items. |
| `hardware/archive/` | Superseded handoffs (`HANDOFF_145.md`, `HANDOFF_rev2.md`). |

## Reading the long docs

The handoffs and `kicad/README.md` are 15-25 KB each, so read only what the task
needs:

- Start from `HANDOFF_ucs125_rev3.md` (this board), then `HANDOFF_rev3.md` for the
  circuit's history: grep their `## ` headings and read the relevant sections,
  not the whole file.
- Open `archive/` only when the current handoff points there or the user asks
  about an older revision.
- Read `kicad/README.md` by section, the same way.
- Query the board with pcbnew scripts or `grep`, never by reading
  `cryocooler.kicad_pcb` whole (it is ~5 MB; reads of it are blocked for Claude).

## PCB layout directives

Standing rules for any schematic or PCB work in `hardware/kicad/` (or a new board):

- **Verify, never assume** — confirm every part against its datasheet before using
  it: exact IC/part number, footprint and package, pinout, supply/IO voltages and
  ratings. Don't rely on memory, naming, or a similar part's library footprint.
- **Part and datasheet links** — every symbol's properties include a link to the
  part (supplier/manufacturer product page) and a link to its datasheet.
- **Reference on orders** — when ordering a part from a supplier, include its
  reference designator(s) (e.g. `U3`, `R12`) in the line's customer-reference field.
- **Test points** — every IC gets at least a minimal set of test points (supply,
  ground, and its key signals/buses), placed beside the part. A test point goes
  on the same side of the board as the part it tests, as close to it as
  possible, so both can be probed without turning the board over.
- **Dense placement** — pack the layout tightly. Leave empty space only where a
  part's datasheet requires it (keep-outs, thermal, isolation clearance) or no
  other arrangement works.
- **Sections mirror the schematic** — group each schematic sheet's components into
  its own PCB region and outline it on silkscreen. Adjacent sections may share a
  border line to save space.
- **Pin 1 markers** — mark pin 1 on every IC, oscillator/crystal, connector and
  other polarized multi-pin part.
- **Part name on the footprint** — when the body is large enough, print the part
  name on it (e.g. `555` on a 555 timer). Keep the reference designator too, just
  not directly under the part.
- **MCU pin names** — for ATmega and ESP32 parts, print the pin names in or around
  the footprint (`GND`, `EN`, `IO1`, `IO2`, `TXD0`, `RXD0`, …).
- **ESP32 antenna** — don't just void copper under the antenna: cut the board out
  beneath it (routed notch, keep-out cleared on all layers), or, if the footprint
  allows, let the antenna overhang the board edge. **Confirm with the user before
  choosing the overhang.**
- **Label board I/O** — clearly silkscreen every input and output: power input and
  its voltage, ground, output signals, etc.
- **Readable silkscreen** — no text may overlap other text, pads, part bodies,
  section lines, open holes or the board edge. Silk may cross a via when the
  board is ordered with filled and capped vias; solder mask text stays on solid
  pour. Reserve room for fixed text (board ID, labels) before placing parts, and
  fail the check rather than ship overlapping text.
- **Every part on the board** — never leave an unplaced part (e.g. at the
  origin or off the edge). An unplaced part is a layout failure, not a warning.
- **Board ID block** — silkscreen a small identification block on every board:
  - the board name (KiCad project or git repo name, e.g. `Cryocooler-Controller`);
  - the revision, using the short git commit ID the fab files were generated from
    (`git rev-parse --short HEAD`, e.g. `rev 4693823`).
  - Keep this block in the same place and format across revisions of the same
    board, so any two copies can be compared at a glance.
- **Trace Angles** - Stick to 0°, 45°, 90° angle traces unless absolutely necessary.
- **STEP 3D models only** — every footprint's 3D model must be a STEP file
  (`.step` or `.stp`). Never use VRML (`.wrl`) models on the PCB.
