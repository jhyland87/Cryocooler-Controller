# General rules (all work in this repo)

## Verify, never assume

Don't assume facts about this project, its hardware, or its tools. Confirm them first:

1. **The codebase:** code, docs, `git log`, and the generated/built output.
2. **Online primary sources:** manufacturer datasheets, library source, official docs.
   Prefer these over memory, forum posts, or search-result snippets.
3. **The user:** ask when the answer is a decision or isn't written down anywhere.

This covers part numbers, pinouts, register maps, library APIs and macros, file
locations, build behaviour, and what the user intends. If something still can't be
confirmed, say so plainly and name what is unverified. Never present a guess as a fact.

## Respect earlier decisions

Before changing a part, design trade-off, or convention, check whether it was a
deliberate choice (`hardware/kicad/DESIGN_REVIEW.md`, the `hardware/HANDOFF_*.md`
notes, commit messages). If it was, say plainly that the change reverses it and what
the reversal costs, and let the user decide. Don't slip a reversal into a list of "fixes".

## No dead code

Don't leave unused or abandoned libraries, dependencies, submodules, files, functions,
config constants, or commented-out code behind. When a change makes something unused,
or you find something already unused, list it for the user and delete it once they
confirm. Never delete it without asking.

## Report honestly

- Report build/test failures as they are, with the output. Never claim something works
  without having run it.
- Say which steps were skipped or couldn't be checked (no hardware on the bench,
  datasheet unavailable, etc.).

## Generated files: never hand-edit

Edit their sources instead. The firmware build regenerates these, and they are
gitignored:

- `include/web_content.h` (from `scripts/embed_web.py`)
- `src/generated/telemetry.pb.c`, `include/generated/telemetry.pb.h` (Nanopb, from `proto/`)
- `dashboard/src/generated/telemetry.{js,d.ts}` (protobufjs, from `proto/`)
- `docs/doxygen/` (Doxygen output)

The schematic files `hardware/kicad/*.kicad_sch` and `sheets/` are committed but
generated by `hardware/kicad/tools/gen_schematic.py`. Change the generator and re-run it.

## Secrets

`include/config/arduino_secrets.h` holds plaintext WiFi credentials. Never commit it,
print it, or paste its contents into chat, logs, or docs.

## Keep docs in sync

When behaviour, wiring, a pin, or a workflow changes, update the doc that describes it
in the same change: `README.md` hardware table, `docs/*.md`, `hardware/kicad/README.md`,
the rules here, the `.claude/skills/`.
