# AGENTS.md

Guidance for AI coding agents and human contributors working in this repo. This
is the canonical, tool-agnostic overview. `CLAUDE.md` imports it. The rules
(coding style, module pattern, hardware design, workflow) live in
[`.claude/rules/`](.claude/rules/), indexed [below](#rules).

## Project overview

ESP32-S3 firmware that automates the cooldown sequence of a cryogenic cooler. A
ten-state machine drives a compressor-based cold stage from room temperature
(~295 K) down to a 78 K setpoint, enforcing thermal/current safety limits,
streaming Protobuf telemetry over WebSocket, and serving a real-time Preact
dashboard over WiFi.

- **Firmware:** C++17, Arduino framework on PlatformIO (`espressif32@5.3.0`).
- **Dashboard:** Preact + MUI + Vite + TypeScript in `dashboard/`, bundled into
  the firmware at build time.
- **Units:** Celsius throughout the firmware (not Kelvin), despite the K figures
  above being how the process is described.
- **No I2C:** every peripheral is on SPI or a GPIO. The fan and pump use LEDC PWM through a BSS138 and PCNT tach counting.

See [`README.md`](README.md) for the hardware table and wiring, and the `docs/`
guides below for subsystem detail.

## Architecture

Every subsystem is a C++ **namespace of free functions** plus a thin
`struct Module : ModuleBase<T>` (CRTP) that gives it a compiler-enforced
lifecycle (`init()` / `service()`, optional `enable`/`disable`/`isEnabled`).
Modules are registered in **declarative `ModuleEntry` arrays** in
[`src/main.cpp`](src/main.cpp); generic helpers (`initGroup`, `serviceWithLog`,
`reportStatus`) drive init and service loops — no per-module boilerplate. The
contract lives in [`include/module.h`](include/module.h). Start there and in
`docs/modules.md` before adding or changing a subsystem.

## Telemetry has two independent output paths

Both are driven from the same module getters and share the `group.field_name`
key convention:

1. **HTTP JSON** — `FrameBuilder` in `src/modules/telemetry.cpp`.
2. **WebSocket binary (Protobuf)** — Nanopb encoder in
   `src/modules/telemetry_pb.cpp`, decoded by
   `dashboard/src/utils/decodeTelemetry.ts`.

`proto/telemetry.proto` is the source of truth for both C++ and TS stubs.
**Never renumber or reuse a proto field number** — it silently corrupts old
clients. Adding a field touches ~8 places; follow `docs/telemetry.md` exactly.

## Build pipeline

`platformio.ini` runs three pre-build scripts **in this order** before compiling:

1. `scripts/compile_proto.py` — Nanopb → `src/generated/telemetry.pb.c` +
   `include/generated/telemetry.pb.h`.
2. `scripts/build_dashboard.py` — `npm ci` + `npm run build` (Vite) → `data/`.
3. `scripts/embed_web.py` — embeds `data/` assets into `include/web_content.h`.

### Commands

```bash
pio run                        # full build (default env: esp32s3)
pio run -t upload              # build + flash over USB
pio device monitor            # serial monitor (115200)
pio test -e native            # host-side unit tests
```

### Fast-iteration flags

```bash
SKIP_DASHBOARD_BUILD=1 pio run   # skip the npm/Vite dashboard build
SKIP_PROTO_BUILD=1 pio run       # skip Nanopb regeneration
```

Environments: `esp32s3` (default), `native` (host unit tests), `esp32s3_test`
(on-device tests).

## API documentation (Doxygen)

The firmware is documented with Doxygen (`/** @file / @brief */`, `@param`,
`@return`). Regenerate HTML docs into `docs/doxygen/html`:

```bash
doxygen Doxyfile
```

Prerequisites (macOS): `brew install doxygen graphviz`. The `Doxyfile` has
`HAVE_DOT = YES`, so Graphviz renders class/call/caller graphs; without `dot`
the docs still build (graphs are skipped). Generated files and `dashboard/` are
excluded from the docs.

**Published docs:** merges to `main` run `.github/workflows/docs.yml`, which
builds these docs and deploys them to GitHub Pages
(`https://jhyland87.github.io/Cryocooler-Controller/`). One-time repo setup:
**Settings → Pages → Source = GitHub Actions.**
