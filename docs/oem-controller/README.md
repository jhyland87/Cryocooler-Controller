# OEM controller reference (STI SuperFilter / SuperLink cryocooler controller)

This folder transcribes the **original Superconductor Technologies (STI) cryocooler controller**'s logic, firmware and
schematics, taken from three STI patents and two product manuals, into formats that are easy to read and analyze.
Nothing here is used by the build of this project's firmware or dashboard.

| Format | Open with |
|---|---|
| `.drawio` diagrams | [diagrams.net](https://app.diagrams.net) (File → Open from → Device) or the draw.io desktop app |
| KiCad project | KiCad 10: open [kicad/oem-controller.kicad_pro](kicad/oem-controller.kicad_pro) |
| Firmware | plain text (TI C2000 C and assembly) |

## Start here

- **[analysis/STATE_MACHINE.md](analysis/STATE_MACHINE.md)**: every source's state machine, cross-mapped (firmware, SuperFilter, SuperLink).
- **[analysis/OVERSTROKE.md](analysis/OVERSTROKE.md)**: everything on overstroke detection and drive back-off.
- **[US6446444/code/INDEX.md](US6446444/code/INDEX.md)**: the transcribed DSP firmware.

## Conventions

- **Verbatim first.** Code, values, refs and labels are kept exactly as printed, typos and drafting errors included.
  Every anomaly is listed in the relevant TRANSCRIPTION_NOTES. Anything inferred rather than stated is marked
  **[inference]** in the docs, or drawn grey and dashed with "inferred" on it in the diagrams.
- **Citations.** Patents and manuals are cited by PDF page number (the copies in this folder), and patent text by
  column. Firmware is cited as `FILE:line` in `US6446444/code/`.
- `source-pages/` folders hold 150 dpi renders of every transcribed page, for side-by-side checking.

## Regenerating

Everything is generated by scripts, so re-running them reproduces the files. Use `python3 -I` from the repo root:

| What | Command |
|---|---|
| Patent diagrams | `python3 -I docs/oem-controller/tools/gen_drawio_patents.py` |
| Manual diagrams | `python3 -I docs/oem-controller/tools/gen_drawio_manuals.py` |
| State diagrams | `python3 -I docs/oem-controller/tools/gen_drawio_states.py` |
| Overstroke diagram | `python3 -I docs/oem-controller/tools/gen_drawio_overstroke.py` |
| Firmware checks | `python3 -I docs/oem-controller/tools/check_code.py` |
| KiCad project + checks | `docs/oem-controller/kicad/tools/check.sh <scratch-dir>` (builds into a scratch dir and checks), then `python3 -I docs/oem-controller/kicad/tools/gen_oem_schematic.py` to write the real project |

The KiCad generator imports `hardware/kicad/tools/kicadgen.py` read-only, so it needs that folder present.
`tools/assemble_code.py` rebuilds the code modules from per-page transcriptions, which are not kept in the repo.
