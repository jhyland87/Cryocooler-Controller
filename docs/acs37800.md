# ACS37800 (SPI) gotchas

The ACS37800 current/power monitor (U18) took several days to bring up on the
rev 1 board. Each item below either caused a failure or sent the debugging the
wrong way. Read this before changing the SPI transport in
[`lib/ACS37800/src/ACS37800.h`](../lib/ACS37800/src/ACS37800.h) or the probe in
`initAcs()` ([`src/modules/amplifier.cpp`](../src/modules/amplifier.cpp)).

Datasheet: [ACS37800](https://www.allegromicro.com/-/media/files/datasheets/acs37800-datasheet.pdf),
"SPI" section (Figures 28 and 30).

## The SPI frame

**1. The whole frame is LSB first, address included.** One 40-bit frame per CS
assertion, in this order: A0..A6, R/W, D0..D31. On an `LSBFIRST` bus that makes
the command byte `0x80 | reg` for a read and `reg` for a write, followed by the
data bytes least significant first.

- **Don't** use `(reg << 1) | 1` on an `MSBFIRST` bus. Many I2C-style examples
  and our first handoff did, and the chip answers that with junk.
- **Mode 3.** Use 0.1 to 10 MHz; the firmware runs at 1 MHz.

**2. MISO returns the previous frame's data.** A read sends the same read
command twice, each with its own CS assertion, and keeps the second response.
A single frame returns whatever the command before it asked for.

**3. Register 0x2A answers even with the wrong bit order.** Its address,
`0101010`, reads the same forwards and backwards. When 0x2A gives sensible
values and every other register reads junk, check the bit order first.

**4. The first frame after `SPI.begin()` is corrupted unless the bus is primed.**
`begin()` leaves SCLK idling low (mode 0). The ESP32-S3 applies a new idle
level only when the next transfer starts, so the first mode-3 frame gets an
extra clock edge and shifts by one bit.

- `ACS37800::primeSPI()` clocks one byte with CS high to fix this.
- `initAcs()` calls it before the first register access; keep that call.
- The same effect broke the ADS1220 on the shared bus after AD9833 (mode 2)
  writes; see `hardware::idleSpiClockLow()` in
  [`include/hardware.h`](../include/hardware.h).

**5. It has its own SPI bus.** The ACS37800 keeps driving MISO while CS is
high, which would corrupt every other device on a shared bus.

## Detecting the chip

**6. The library can't tell when SPI fails.** `getLastError()` is always 0 on
SPI, and an unpowered or absent chip reads back numbers like any other. The
write-back probe in `initAcs()` is the only presence check.

**7. Probe with shadow register 0x1F, compared on bits 24:0.**

- **Shadow 0x1F holds only bits 24:0.** Writing a full 32-bit word and
  comparing all of it fails (we wrote `0xFF557FFF` and read back `0x01557FFF`).
- **EEPROM 0x0F carries ECC in bits 31:26.** Mask it to bits 24:0 before
  using it as the value to restore.
- **Unlock first:** write the access code `0x4F70656E` to 0x2F before any
  shadow write.
- **What the probe does:** change only the sample-count field, read it back,
  then restore 0x1F from 0x0F.

**8. Don't probe with 0x30 (CUSTOMER_ACCESS).** It reads 0 even after a
correct access code, while shadow writes still work.

**9. A probe that only rejects patterns gives false results.** A
"repeating-nibble = junk" check passed floating-MISO noise as a real reply and
rejected a legitimate `0x00000000`. Write a value, then read it back.

## Telling a bad chip from a bad frame

**10. Wrong-frame junk looks like hardware failure.** With the wrong bit order
every register read back a repeating word (`0xDDDDDDDD`, `0xBBBBBBBB`,
`0x00000000`), much like a floating MISO.

- We concluded at one point that U18 was an I2C-only part and needed
  replacing. It was the frame.
- **Before suspecting the part:**
  1. Confirm the SPI variant from its marking.
  2. Confirm the isolated side has power.
  3. Read the factory trim registers 0x0B..0x0E: on a working chip and frame
     they are non-zero and stable.

**11. An unpowered isolated side also reads junk.** The ACS37800 sits behind a
digital isolator. Without power on the isolated side, the isolator's MISO
output floats and picks up clock coupling.

| Board | Isolator | Isolated-side supply to check |
|-------|----------|-------------------------------|
| Rev 1 | ISO7741 | PS1, JP3, ISO_3V3 |
| Rev 3 | ISOW7741 (U17), with an integrated supply | U17 EN, ISO_5V |

The chip itself has no EN pin. The "EN" on the Pololu carrier switches its
isolated supply.

## Using it

**12. RMS registers are too slow for spikes.** Back-EMF and current spikes
show up in the fault flags (0x2D, overcurrent and over/undervoltage). Watch
those, not 0x20/0x21 polled faster.

**13. Board parameters set the scaling.**

- Rev 1 uses `setBoardPololu(4)`.
- Rev 3 uses `setBoardParameters(15 A, RISO 4 MΩ, RSENSE 4.02 kΩ)`.

A wrong set gives plausible but wrong V, A and W. Check against a meter.
